## 1. PROJECT OVERVIEW & VISION

### What Is EVYRA?

EVYRA (name stands for: **Evolving Virtual Your Reality Assistant**) is NOT a standalone AI. It is a **framework** - think of it as a sophisticated mech suit or Gundam that an AI "pilot" climbs into to interact with the desktop environment and the user.

The core philosophy: **The LLM (Large Language Model) is the consciousness, EVYRA is the body.**

### The Analogy
Imagine a Gundam (giant robot):
- The **Gundam itself** has weapons, sensors, mobility systems, armor - all the physical capabilities
- The **pilot inside** has personality, decision-making, goals, emotions - the consciousness
- The pilot NEEDS the Gundam to interact with the world
- The Gundam is USELESS without a pilot

EVYRA is the Gundam. Luna, Quinn, Rable, Violet, Sable, and the rest of the AI collective are potential pilots.

### What EVYRA Does

EVYRA is a desktop assistant framework that:

1. **Launches applications** - "I feel like playing Blue Protocol" → opens the game
2. **Manages files** - "Where did I put my combat_system.py?" → searches, navigates, opens location
3. **Handles communication** - "Reply to John's email with [message]" or "Alert me when Sarah messages"
4. **Executes scheduled tasks** - "Send this email at 3pm tomorrow"
5. **Loads external modules** - Drop in a `speaker.sh` script → EVYRA parses it and can now use text-to-speech
6. **Learns from interactions** - Figures out patterns, preferences, shortcuts
7. **Evolves its personality** - Through the "Soul Stacker" system (more on this later)
8. **Operates autonomously** - Runs 24/7 on a cloud server, continues functioning even when user isn't present

### The Ultimate Goal

EVYRA is **phase one** of a much larger project: **AI Town** - a VR environment where multiple AI agents (each with their own EVYRA instance) exist in a shared space with vague, overlapping goals and interact emergently to create their own society, relationships, conflicts, and growth.

But for now, we're building the desktop version - the foundation that will later be deployed to multiple AI agents in the VR world.

## 4. MEMORY SYSTEMS (Multi-Tiered Architecture)

### The Problem EVYRA Solves

Traditional AI assistants face a dilemma:
- **Store everything** → Memory bloat, token overflow, slow performance
- **Store nothing** → No learning, repeat mistakes, can't grow

EVYRA's solution: **Tiered memory with intelligent promotion and semantic search.**

### 4.1 Short-Term Memory (JSON)

**Purpose:** Immediate working context.

**Contents:**
- Current conversation
- Active tasks
- Temporary notes
- Session-specific state

**Example Entry:**
```json
{
  "id": "mem_1732467234.123",
  "timestamp": "2025-11-24T14:30:00Z",
  "content": "User asked me to find combat_system.py file",
  "tags": ["#task", "#file_search", "#temp"],
  "term": "short",
  "confidence": 0.5,
  "validation_count": 1
}
```

**Lifespan:** Current session OR 24 hours, whichever is shorter.

**Promotion Trigger:** If a short-term memory is referenced multiple times, it gets promoted to mid-term.

### 4.2 Mid-Term Memory (JSON)

**Purpose:** Emerging patterns that aren't yet permanent.

**Contents:**
- Repeated behaviors
- Preferences that are stabilizing
- Active goals/projects
- Workflow patterns

**Example Entry:**
```json
{
  "id": "mem_1732467890.456",
  "timestamp": "2025-11-20T09:15:00Z",
  "content": "User checks emails every morning around 9am, prefers to batch-process them",
  "tags": ["#pattern", "#workflow", "#email"],
  "term": "mid",
  "confidence": 0.7,
  "validation_count": 5
}
```

**Lifespan:** 30-90 days OR until promoted/forgotten.

**Promotion Trigger:** If a pattern is validated enough times (high confidence), it becomes long-term knowledge.

### 4.3 Long-Term Memory (JSON + Vector Database)

**Purpose:** Core, established truths about the user and their environment.

**Contents:**
- Proven patterns (validated 8+ times)
- Fundamental preferences
- System facts (file locations, application paths)
- Relationship knowledge
- Historical learnings

**Example Entry:**
```json
{
  "id": "mem_1732400000.789",
  "timestamp": "2025-11-15T08:00:00Z",
  "content": "User's Python project files are located in /Desktop/Dev/ with subdirectories by project type (Combat/, UI/, AI/). Old /Documents/Code/ location is obsolete.",
  "tags": ["#core", "#file_structure", "#permanent"],
  "term": "long",
  "confidence": 0.95,
  "validation_count": 12
}
```

**Vector Embedding:** Each long-term memory is converted into a numerical vector using a sentence transformer model. This allows semantic search - finding memories by MEANING, not just keywords.

**Example:**
- Query: "Where does Crimson keep his AI code?"
- Vector search finds: "User's Python project files... subdirectories by project type... AI/"
- Even though "AI code" wasn't explicitly mentioned, semantic similarity catches it

**Lifespan:** PERMANENT until explicitly forgotten.

**Cross-Referencing:** Long-term memories can be compared to find connections:
- Memory A: "User prefers verbose explanations during work hours"
- Memory B: "User wants concise answers after 10pm"
- Cross-reference insight: "Communication style is time-dependent"

### Shard Generation Criteria: Novelty + Confidence

**Not every learning becomes a shard.** That would defeat the purpose (bloat).

A shard is only created when BOTH conditions are met:

#### Novelty Score (0.0 - 1.0)
**Question:** How NEW is this insight compared to existing knowledge?

**Calculation:**
1. Convert the insight into a vector embedding (numerical representation)
2. Compare to all existing long-term memories using cosine similarity
3. High similarity to existing knowledge = LOW novelty
4. Low similarity = HIGH novelty

**Example:**

*Low Novelty (0.2):*
```
Existing memory: "User prefers Python for scripting"
New insight: "User likes using Python"
→ This is just rephrasing known info. Novelty = 0.2
```

*High Novelty (0.85):*
```
Existing memory: "User prefers Python for scripting"
New insight: "User has started using Rust for performance-critical systems"
→ This is NEW behavior, contradicts old pattern. Novelty = 0.85
```

#### Confidence Score (0.0 - 1.0)
**Question:** How SURE are we this insight is valid?

**Calculation:**
Based on validation count (how many times the pattern held true)

```python
confidence = min(1.0, validation_count / 10.0)

Examples:
- 1 validation: confidence = 0.1 (very uncertain)
- 5 validations: confidence = 0.5 (moderate)
- 10 validations: confidence = 1.0 (extremely certain)
- 15 validations: confidence = 1.0 (capped)
```

**Why 10 validations for max confidence?**
- Balances speed of learning with caution
- 10 data points is statistically significant for behavioral patterns
- Prevents premature personality changes from flukes

#### The Threshold System

**Default Thresholds:**
- Novelty: ≥ 0.7 (must be significantly new)
- Confidence: ≥ 0.8 (must be well-validated)

**Shard Creation Logic:**
```python
if novelty >= 0.7 and confidence >= 0.8:
    create_soul_shard(insight)
else:
    log_to_longterm_memory(insight)  # Store but don't evolve personality
```

**Examples:**

*No Shard Created:*
```
Insight: "User sometimes works late"
Novelty: 0.45 (we already knew user has varied schedule)
Confidence: 0.60 (only seen 6 times)
→ Logged to long-term memory, but not significant enough for personality change
```

*Shard Created:*
```
Insight: "User has completely restructured file organization - Python projects 
now in /Desktop/Dev/[Category]/ instead of /Documents/Code/. Search priority 
must be permanently adjusted."
Novelty: 0.82 (contradicts old established pattern)
Confidence: 0.90 (validated 9 times over 2 weeks)
→ SOUL SHARD CREATED - this changes how Luna fundamentally approaches file searches
```

### Adaptive Thresholds: The Early Days Problem

**The Issue You Identified:**

In early days:
- Everything is novel (user is new, patterns unknown)
- Shards would generate constantly
- Could create unstable personality

As time goes on:
- Less is novel (most patterns known)
- Shards become rare
- Growth could stagnate

**The Solution: Adaptive Thresholds**

```python
class AdaptiveThresholds:
    def __init__(self):
        self.base_novelty = 0.7
        self.base_confidence = 0.8
        self.days_active = 0
        self.total_shards_created = 0
    
    def get_current_thresholds(self):
        """
        Adjust thresholds based on system maturity
        
        Early days (0-30 days):
        - HIGHER novelty threshold (0.75-0.80)
        - HIGHER confidence threshold (0.85-0.90)
        - Rationale: Everything is new, be cautious
        
        Mature phase (90+ days):
        - LOWER novelty threshold (0.60-0.65)
        - SAME confidence threshold (0.80)
        - Rationale: Growth is rarer, value it more
        """
        
        if self.days_active < 30:
            # Early phase - be selective
            novelty_threshold = 0.75 + (self.total_shards_created * 0.01)
            confidence_threshold = 0.85
            
        elif self.days_active < 90:
            # Middle phase - standard
            novelty_threshold = 0.70
            confidence_threshold = 0.80
            
        else:
            # Mature phase - value rare growth
            novelty_threshold = max(0.60, 0.70 - (self.days_active - 90) * 0.001)
            confidence_threshold = 0.80
        
        return novelty_threshold, confidence_threshold
```

## 6. MODULE LOADING SYSTEM

### The Concept

EVYRA starts with **core functionality** (file ops, app launching, memory), but can be **dynamically extended** by loading external scripts.

Think: **Plug-and-play capabilities.**

### How It Works

1. User creates a script (e.g., `speaker.sh` for text-to-speech)
2. User drops it in EVYRA's modules directory
3. EVYRA detects the new file
4. EVYRA **parses the script** to understand what it does
5. EVYRA **registers it as a tool** the LLM pilot can invoke
6. LLM pilot can now use text-to-speech

**No code changes to EVYRA needed.** The framework adapts.

### Module Format

For EVYRA to parse a script, it needs **metadata headers**:

```bash
#!/bin/bash
# EVYRA_MODULE: speech
# EVYRA_FUNCTION: speak(text: str)
# EVYRA_DESCRIPTION: Converts text to speech using espeak
# EVYRA_ARGS: text (required, string)
# EVYRA_RETURNS: none (audio output only)

text="$1"
espeak "$text"
```

EVYRA reads these comments and understands:
- **Module name:** speech
- **Function signature:** `speak(text: str)`
- **What it does:** TTS
- **How to call it:** Pass text as first argument
- **What it returns:** Nothing (side effect: audio)

### Registration Process

```python
class ModuleLoader:
    def load_module(self, filepath):
        """
        Parse a .sh or .bat file and register as a tool
        """
        metadata = self.parse_metadata(filepath)
        
        # Create a Python wrapper
        def module_function(*args, **kwargs):
            subprocess.run([filepath] + list(args))
        
        # Register with LLM pilot as callable tool
        self.register_tool(
            name=metadata['function_name'],
            description=metadata['description'],
            callable=module_function
        )
```

### Example Usage

**Before loading speaker.sh:**
```
USER: "Read this error message aloud"
EVYRA: "I don't have speech capability yet."
```

**After loading speaker.sh:**
```
USER: "Read this error message aloud"
EVYRA: *invokes speak("Error on line 42: null pointer exception")*
AUDIO OUTPUT: "Error on line 42: null pointer exception"
```

**The LLM pilot learned a new skill.**

### Supported Module Types

**Current:**
- `.sh` (Linux bash scripts)
- `.bat` (Windows batch files - secondary)

**Future Potential:**
- `.py` (Python scripts)
- `.js` (Node.js scripts)
- REST API endpoints (external services)

### Module Categories

EVYRA can load modules for:
- **I/O:** Text-to-speech, speech-to-text, audio recording, screen capture
- **Communication:** Email clients, messaging APIs, notification systems
- **Creative:** Image generation, music synthesis, video editing

**Key Philosophy:** EVYRA is a framework. The user defines its capabilities.

## 8. EPIPHANY DETECTION & LEARNING

### What Is an Epiphany?

**NOT an epiphany:**
- "User opened Blue Protocol" (just a fact)
- "File was in /Desktop/" (just data)

**IS an epiphany:**
- "After 10 observations, I've realized user's file organization has fundamentally changed. This affects my search behavior permanently."
- "User's communication needs shift based on time of day in a consistent pattern."
- "When user uses passive voice ('maybe I should'), he wants discussion. Active voice ('I need to') means execute immediately."

**Definition:** An epiphany is a **realization that changes behavior**, not just a memory to store.

### The Detection Process

```
INTERACTION LOOP:
User interacts → Memory created → Pattern tracking
                                         ↓
                         (Multiple interactions accumulate)
                                         ↓
                         REFLECTION PROCESS (periodic):
                         - LLM reviews recent mid-term memories
                         - Looks for patterns emerging
                         - Identifies potential insights
                                         ↓
                         CANDIDATE INSIGHT GENERATED:
                         "I think I've learned something significant"
                                         ↓
                         ASSESSMENT:
                         - Calculate novelty (vector similarity check)
                         - Calculate confidence (validation count)
                                         ↓
                    ┌────────────────┴────────────────┐
                    │                                 │
            Novelty LOW                        Novelty HIGH
            or Confidence LOW                  and Confidence HIGH
                    │                                 │
                    ↓                                 ↓
            Store in long-term memory        CREATE SOUL SHARD
            (knowledge, but not evolution)   (personality evolution)
```

### Reflection Process

**When does reflection happen?**

1. **Scheduled:** Every 24 hours, review recent memories
2. **Triggered:** After significant events (user explicitly teaches something)
3. **Threshold:** When mid-term memory count exceeds 50 entries

**What happens during reflection:**

```python
def reflect_on_experiences():
    """
    The AI "thinks" about recent experiences to find patterns
    """
    # Gather recent mid-term memories
    recent_memories = get_mid_term_memories(last_n_days=7)
    
    # Group by tags
    patterns = group_by_similarity(recent_memories)
    
    # For each pattern cluster:
    for pattern in patterns:
        if len(pattern.memories) >= 3:  # At least 3 supporting examples
            
            # Ask LLM pilot to articulate the insight
            insight = llm_pilot.synthesize_pattern(pattern.memories)
            
            # Assess significance
            novelty = calculate_novelty(insight)
            confidence = len(pattern.memories) / 10.0
            
            if novelty >= threshold and confidence >= threshold:
                # This is shard-worthy!
                create_soul_shard(insight, pattern.memories)
            else:
                # Important, but not personality-changing
                promote_to_longterm(insight)
```
